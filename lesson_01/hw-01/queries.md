# Запросы к коллекции · занятие 1

**Предметная область:** объявления о продаже техники
**База и коллекция:** marketplace.listings
**Сколько документов:** 5

---

## 1. Точное совпадение строки

```js
{ category: "смартфоны" }
```

Найдено: **1 из 5**
Что искали: объявления из категории «смартфоны». Строка должна совпасть
полностью и с учётом регистра — «Смартфоны» или «смартфон» уже не подойдут.

## 2. Поле внутри вложенного объекта

```js
{ "seller.city": "Ярославль" }
```

Найдено: **2 из 5**
Что искали: объявления продавцов из Ярославля. Город лежит внутри объекта
`seller`, поэтому путь пишется через точку и обязательно в кавычках —
иначе MongoDB воспримет `seller.city` как два разных поля.

## 3. Элемент массива

```js
{ tags: "торг" }
```

Найдено: **2 из 5**
Что искали: объявления, у которых в массиве `tags` есть элемент «торг».
MongoDB проверяет элемент массива тем же синтаксисом, что и обычное поле,
без оператора `$in` или `$elemMatch`.

## 4. Оператор сравнения

```js
{ price: { $gt: 23000 } }
```

Найдено: **3 из 5**
Что искали: объявления дороже 23 000 ₽. Подходят iPhone (52 000),
Lenovo (47 000), Dell (24 000). Монитор за 24 000 попадает, потому что
`$gt` — строгое «больше», а не «больше или равно».

## 5. Наличие поля

```js
{ delivery: { $exists: true } }
```

Найдено: **1 из 5**
Что искали: объявления, где вообще есть поле `delivery`. Подходят только
наушники Sony — у остальных четырёх документов такого поля нет.
`$exists: true` не проверяет значение, только факт наличия поля.

## 6. Сломанный запрос

```js
{ price: { $gt: } }
```

Что произошло: **ошибка разбора**

Как это видно на экране: поле фильтра подсвечивается красным, кнопка Find
неактивна, под полем появляется сообщение `Expected a value` / «invalid
query». Счётчик внизу не меняется — запрос не отправляется на сервер.

Почему так: у оператора `$gt` не указано значение справа, JSON невалиден,
парсер Compass не может собрать документ-фильтр и отклоняет ввод до
отправки. Это не «пустой результат» — до сервера запрос просто не доходит.

## Цена дубликата

В документах повторяется название города внутри `seller.city`:
«Ярославль» — в двух объявлениях, «Москва» — тоже в двух. Если коллекция
вырастет до 200 объявлений, при переименовании города («СПб» →
«Санкт-Петербург») придётся обновлять все документы продавцов из этого
города через `updateMany`. Одна ошибка в фильтре — и часть документов
останется со старым названием, часть — с новым.

Оставил дубликат потому, что город — короткая и почти неизменяемая строка,
а объявление всегда читается вместе с продавцом: хранить его рядом быстрее
и проще, чем делать `$lookup` в отдельную коллекцию `sellers`. Если бы у
города появились «тяжёлые» поля (регион, зоны доставки, тарифы), которые
часто меняются, — вынес бы продавцов в отдельную коллекцию.
