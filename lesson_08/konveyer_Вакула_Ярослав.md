## Письмо 1. Ревью конвейеров

### 1. Выручка доставленных заказов от ноутбуков.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — неверно
- Комментарий: из за того что в $group не указано точно по какому полю проходим указан просто $items, но в поле $group суммируется поле $total, которое относится ко всему заказу целиком. поэто стоимость всего заказа прибавляется столько раз, сколько ноутбуков в нем было
- Исправленный конвейер:

```js
[
  { $match: { status: "доставлен" } },
  { $unwind: "$items" },
  { $match: { "items.category": "ноутбуки" } },
  { $group: { _id: null, revenue: { $sum: "$items.price" } } }
]
```

### 2. Сколько заказов в пути в каждом городе.

- Решение: есть ошибка — $project перед стадией, которой нужно отброшенное поле — верно
- Комментарий: в $match работаем с status, но в проекции его у нас нет
- Исправленный конвейер:

```js
[
  { $match: { status: "в пути" } },
  { $project: { number: 1, delivery: 1 } },
  { $group: { _id: "$delivery.city", orders: { $sum: 1 } } },
  { $sort: { _id: 1 } }
]
```

### 3. Номер первого по дате заказа каждого покупателя из трёх: c-007, c-011, c-018.

- Решение: есть ошибка — $first или $last без $sort перед $group — верно
- Комментарий: за счет того что сорт идет после гроп, то в гроуп выдаст первый попавшийся документ, а не по дате
- Исправленный конвейер:

```js
[
  { $match: { customer_id: { $in: ["c-007", "c-011", "c-018"] } } },
  { $sort: { date: 1 } },
  { $group: { _id: "$customer_id", first: { $first: "$number" } } },
  { $sort: { _id: 1 } }
]
```

### 4. Пять самых дорогих доставленных заказов.

- Решение: есть ошибка — стадии стоят не в том порядке: $limit срабатывает раньше отбора — верно
- Комментарий: Лимит срабатывает раньше матч, поэтому сначала берется 5 дорогих, а затем отсеиваются недоставленные. Чтобы получить пять самых дорогих именно доставленных, стадию матч надо перенести в начало конвейера
- Исправленный конвейер:

```js
[
  { $match: { status: "доставлен" } },
  { $sort: { total: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, number: 1, total: 1 } }
]
```

### 5. Выручка доставленных заказов по способам оплаты.

- Решение: есть ошибка — путь к полю записан без знака $ — верно
- Комментарий: в стадии $group путь к полю payment.method записан без знака $ в начале. Из-за этого MongoDB воспринимает его как константную строку
- Исправленный конвейер:

```js
[
  { $match: { status: "доставлен" } },
  { $group: { _id: "$payment.method", revenue: { $sum: "$total" } } }
]
```

### 6. Сколько штук смартфонов продано в доставленных заказах.

- Решение: есть ошибка — условие на элемент массива проверено до $unwind — проходят заказы целиком — верно
- Комментарий: Условие на категорию "смартфоны" проверяется до стадии $unwind, поэтому в выборку попадают заказы целиком
- Исправленный конвейер:

```js
[
  { $match: { status: "доставлен", "items.category": "смартфоны" } },
  { $unwind: "$items" },
  { $match: { "items.category": "смартфоны" } },
  { $group: { _id: null, qty: { $sum: "$items.qty" } } }
]
```

### 7. Средний чек доставленных заказов в каждом городе, округлённый до рубля, по убыванию.

- Решение: конвейер верный — верно
- Комментарий: Конвейер верный. Стадия $match отбирает только доставленные заказы. $group группирует их по городу $delivery.city и считает среднее значение чека $avg: "$total". Затем $project округляет полученное среднее до целого числа 0 знаков после запятой с помощью оператора $round. В конце $sort выстраивает города по убыванию среднего чека.

### 8. Три самых продаваемых по штукам товара в доставленных заказах.

- Решение: конвейер верный — верно
- Комментарий: Стадия $match отбирает доставленные заказы. $unwind разворачивает массив товаров. $group правильно группирует данные по названию товара и суммирует их количество. Стадия $sort выстраивает товары по убыванию суммарного количества, а $limit оставляет только топ-3

## Письмо 4. Свои конвейеры

### 1. Доставленные заказы по способу доставки: _id — способ (delivery.type), orders — число заказов, revenue — выручка. По убыванию revenue.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $group: { 
      _id: "$delivery.type", 
      orders: { $sum: 1 }, 
      revenue: { $sum: "$total" } 
  } },
  { $sort: { revenue: -1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 2. Коллекция products. Средняя цена товаров каждой категории, округлённая до рубля: _id — категория, avg — средняя цена. По возрастанию avg.

```js
db.products.aggregate([
  { $match: {} },
  { $group: { _id: "$category", avg: { $avg: "$price" } } },
  { $project: { avg: { $round: ["$avg", 0] } } },
  { $sort: { avg: 1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 3. Покупатели, у которых сумма доставленных заказов больше 400 000: _id — customer_id, spent — сумма. По убыванию spent.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  { $group: { _id: "$customer_id", spent: { $sum: "$total" } } },
  { $match: { spent: { $gt: 400000 } } },
  { $sort: { spent: -1 } }
])
```

- Результат совпадает с нужным, запусков: 1

### 4. Для каждого города — массив номеров отменённых заказов по возрастанию номера: _id — город, numbers — массив. Города по алфавиту.

db.orders.aggregate([

### 5. Одним запросом по доставленным заказам: в поле total — массив из одного документа { orders: число заказов }, в поле top — три товара с наибольшим числом штук (_id — название, qty — штуки), по убыванию qty, при равенстве — по названию.

```js
db.orders.aggregate([
  { $match: { status: "доставлен" } },
  {
    $facet: {
      total: [
        { $count: "orders" }
      ],
      top: [
        { $unwind: "$items" },
        { $group: { 
            _id: "$items.title", 
            qty: { $sum: "$items.qty" } 
        } },
        { $sort: { qty: -1, _id: 1 } },
        { $limit: 3 }
      ]
    }
  }
])
```

- Результат совпадает с нужным, запусков: 1
